# Visual quality checklist

Apply this checklist to every route, pane, dialog, menu and meaningful UI state before calling it visually verified. Use the live browser preview and record the viewport and state in `AUDIT.md`.

## Checks for each surface

- [ ] **Insets and wrapping:** primary text, headings, controls and dividers have balanced space from every edge. Long labels, paths and output wrap or scroll inside their own region; no text runs to a pane edge.
- [ ] **Containment:** no clipping, overlap, accidental horizontal page scrolling or controls outside their owner. Scrollbars belong to the intended surface. Split-pane grips stay on the seam, and are hidden when the pane is an overlay.
- [ ] **Responsive layout:** inspect 1536×855 and 1280×720 desktop layouts, then 768×855 and 390×844 when the surface supports narrow widths. Check the opened and closed pane/dialog states.
- [ ] **Hierarchy and density:** spacing establishes groups before borders or cards; sparse views do not retain large empty frames; routine actions are compact icon buttons with accessible names and tooltips. Keep text labels for form submission and decisions that need wording.
- [ ] **State coverage:** inspect each code-supported empty, populated, loading, error, disabled, success, active, paused, stopped or cancelled state that applies. Confirm the state is understandable without colour alone.
- [ ] **Keyboard and accessibility:** controls have accessible names, visible focus, logical order and keyboard operation; dialogs contain focus and close predictably; tabs keep the selected item visible after resize or selection.
