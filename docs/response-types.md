# Response types

## Product comparison

| Harness | Strong response patterns | Product implication for Tribe |
| --- | --- | --- |
| ChatGPT | Data analysis can show interactive tables with selection and CSV export, and static or interactive charts. Interactive charts currently cover bar, line, pie and scatter; static charts also include heat maps, radar charts, treemaps, bubble charts and waterfalls. | Keep exact values inspectable beside visuals and let users export them. Tribe provides searchable, sortable, paged CSV/TSV previews and bounded XLSX worksheet previews with selectable ranges and source context. [Data analysis](https://help.openai.com/en/articles/8437071-data-analysis-with-chatgpt), [table and chart workflows](https://help.openai.com/en/articles/9213685-extracting-insights-with-chatgpt-data-analysis) |
| Claude | Artifacts turn substantial outputs into reusable documents, diagrams, SVG images, websites and interactive React components, shown beside chat with versions. | Preserve the existing shared documents and sandboxed interactive apps for outputs that need iteration or reuse. [Artifacts](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them) |
| Gemini API | Code execution accepts files and returns Matplotlib graph images inline. Image manipulation through code execution is model-specific; the current docs call out Gemini 3 Flash. | Keep bounded analysis local to Tribe and render common charts natively; use provider-native execution only where its model and limits justify it. [Code execution](https://ai.google.dev/gemini-api/docs/code-execution) |
| Pydantic AI | `BinaryContent` supports image, audio, video and document inputs when the chosen model supports them. Its `ImageGeneration` capability can use native image tools or a direct image-generation model through `ImageGenerator`. | Keep attachment support model-gated, offer a direct image-model fallback when the chat model cannot generate images, and persist results through Tribe's managed artifact store. [Multimodal input](https://pydantic.dev/docs/ai/core-concepts/input/), [image generation](https://pydantic.dev/docs/ai/guides/image-generation/) |

These are complementary patterns rather than one universal output format. Tribe renders Markdown/GFM tables, Mermaid diagrams, Markdown images, shared documents and sandboxed interactive apps. It passes image, audio and video attachments as model inputs, rejecting modalities that known model metadata marks as unsupported; when metadata is absent, the provider decides whether the input is accepted. Attached images are previewed in the conversation, and supported audio/video attachments have native playback in chat and the Artifacts view. Playback does not imply transcription: audio understanding remains dependent on the selected model. The highest-value response types are native chat charts with exact, inspectable data and export, provider-backed image generation persisted as managed chat artifacts, deterministic analysis of attached tabular files, and readable previews for common documents and media.

The built-in `data-visualisation` skill carries detailed chart, table-analysis and PDF extraction guidance. Agents discover and load it for relevant tasks instead of carrying the full chart specification in every request.

## Initial response contract

Chat Markdown supports a `chart` JSON fence for bar, stacked bar, 100% stacked bar (`percent-stacked-bar`), horizontal bar, line, area, scatter, bubble, waterfall, treemap, radar, funnel, histogram, boxplot, pie and heatmap charts. Cartesian charts and histograms use `{ "x": "Jan", "y": 12 }` rows or named series; stacked bars use at least two named series over the same 2–20 categories, require non-negative values, and scale to each category total; use grouped bars to compare series side by side. The `percent-stacked-bar` type requires at least two named series over the same 2–20 categories, non-negative values and a positive total per category. It normalises each category to 100% to compare mix when totals differ; its table and CSV retain the source values and shares. Horizontal bars place the category in `x` and value in `y` and support up to 20 categories. Histogram `x` values are bin labels and `y` values are counts. Bubble charts use three numeric measures: `{ "x": 12, "y": 24, "size": 8, "label": "Segment A", "series": "North" }`; `size` is non-negative and represents bubble area, while label and series are optional.

Radar charts compare 2–8 named options across the same 3–8 criteria. Use `series: [{"name":"Tribe","data":[{"x":"Ease of setup","y":4.4}]}]`; every series must include every criterion, values must be non-negative, and optional `maxValue` sets a shared scale (otherwise it uses the highest score). Funnels use 2–12 named stages with positive initial and non-increasing non-negative counts; the chart reports conversion from the preceding stage and from the initial stage. Waterfalls use `{ "label": "Expansion", "value": 20 }` for a change, or `{ "label": "Ending revenue", "value": 110, "type": "total" }` to set an absolute running total. Types default to change; totals reset the cumulative value. Treemaps use `{ "label": "Compute", "value": 52, "group": "Infrastructure" }`; positive rectangle areas represent values, groups are optional but must be present on every row when used, and each group gets a distinct colour. Treemaps allow 120 categories and 8 groups. Pie data uses `{ "label": "North", "value": 12 }` rows. Boxplots use `{ "label": "Team A", "min": 2, "q1": 4, "median": 6, "q3": 8, "max": 10 }` rows. Heatmaps use `{ "x": "Monday", "y": "9am", "value": 12 }` cells with unique x/y pairs, up to 20 categories on each axis and 240 cells total. A rendered chart includes inspectable values, CSV export for analysis, and SVG and PNG exports for sharing. Invalid chart JSON stays visible as a normal code block. The renderer limits chart sizes and uses React-generated SVG elements rather than executing chart code. Image generation is a separate profile grant; generated PNG, JPEG and WebP results are stored as chat artifacts and displayed inline. New role profiles leave image generation off by default because provider use may incur extra charges.

The `image_generation` capability is a separate profile grant and remains off by default because provider use may incur extra charges. In Settings → Models, users can select a direct image model fallback for roles whose chat model does not provide native image generation. OpenAI choices include [GPT Image 2.5 Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare) for fast everyday generation and [GPT Image 2.5 Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst) for precision workflows; GPT Image 2 remains available for existing setups. Google Gemini 3.1 Flash Image and xAI Grok Imagine are also available. The selected model uses the provider's saved credential; generated PNG, JPEG and WebP results are saved as chat artifacts and displayed inline. Native model image tools remain available when supported. The provider cannot be disabled while it is selected as the workspace image fallback.

The `data_analysis` capability is granted to the default Planner, Builder and Reviewer profiles and can be granted to other roles. It profiles and aggregates chat-attached CSV, TSV and XLSX files with bounded row, column, file-size and expanded-workbook limits. Profiling reports column types, missing values, numeric ranges and means, ISO date ranges, and common categories. A column is typed as a date only when all non-empty values parse as ISO dates or times; mixed or ambiguous values remain categories. XLSX analysis selects a worksheet by name and supports `header_rows` from 1 to 5 to combine stacked column headings; saved transformations retain this setting for replay. Formula cells use cached workbook values and may be blank if Excel has not recalculated the workbook. The workbook preview marks formula cells with no saved result and shows the formula in the cell details; recalculate the workbook to refresh those results. Grouped analysis supports counts, numeric sums, means, minima, maxima and quartiles, with an optional exact-match filter. Set `date_bucket` to `day`, ISO `week`, `month`, `quarter` or `year` to group an ISO date/time column chronologically; timestamps with offsets are normalised to UTC and invalid dates are counted as skipped. Non-quartile group summaries return chart-ready series. Results include chart-ready numeric values and decimal text; it reads only artifacts in the active chat and never executes attachment contents. XLSX previews render common percentage, currency and decimal formats, display dates in ISO form, and include both displayed and stored values when a selected range is shared. Unsupported custom number formats remain visible as stored values, with the Excel format available in the cell detail. The same capability extracts bounded, layout-oriented text from selected pages of searchable PDFs and heuristically extracts tables using drawn lines or aligned text. PDF artifacts open in an inline page viewer rendered locally to bounded PNG pages with PDFium, with previous/next navigation and a direct download action; extracted tables should be checked against the source page, and agents should cite its page number. Pages without extractable text can be passed to `ocr_pdf_pages`, which renders up to five pages and performs local CPU OCR. The bundled model supports English, Simplified and Traditional Chinese, Japanese, French, German, Spanish, Italian, Portuguese, Dutch, Vietnamese and Turkish. Results include page provenance, per-page mean confidence, low-confidence line counts and image/text limits; OCR can misread names, figures and table structure, so agents should cross-check important values against the original page.

`create_tabular_analysis_artifact` saves an intentional transformed CSV and a JSON record containing its exact source artifact, SHA-256 checksum, worksheet, filters, projection, sort/group/pivot operation, row counts and output checksum. Up to 20 filters support `eq`, `neq`, case-insensitive `contains`, `gt`, `gte`, `lt`, `lte`, `blank` and `not_blank`. Range comparisons accept numeric values or ISO dates/times; incompatible cell values are skipped and counted. Column selection, sorting, grouped count/sum/mean/min/max, and two-way pivots with count/sum/mean are also supported. Grouped summaries can bucket an ISO date/time column by day, ISO week, month, quarter or year; timestamps with offsets are normalised to UTC, output groups are chronological, and invalid or blank dates are counted as skipped. Pivots cap distinct column categories at 50 and output row groups at 5,000. Their chart-ready series include up to 8 categories, 30 row groups and 240 points, matching the chart renderer limits. Grouped aggregates also include a chart-ready series when numeric values are available; its truncation flag reflects omitted groups or values. Other output is capped at 5,000 rows; sorting is bounded to a 24 MB in-memory buffer and all transformed CSV outputs to 9 MB. `replay_tabular_analysis_artifact` re-reads only the referenced source in the same chat, verifies the source checksum, reruns the deterministic operation, and checks the output checksum before saving another CSV. Earlier records using exact-match filters remain replayable. The record is provenance, not a copy of source data; replay fails clearly if the source is unavailable or the saved operation no longer reproduces the recorded output.

Use charts for trends and comparisons, tables for exact values, Mermaid for systems and processes, images for visual references, and interactive apps when users need to manipulate or reuse a small tool. A chart does not replace a short written interpretation or data provenance.

## Cohort priorities

- **Data analysts:** trend, category, bridge, composition, conversion funnel and part-to-whole charts; exact values; compact data tables; CSV/TSV/XLSX inputs; reproducible transformations and pivots; and searchable or scanned PDF pages and tables.
- **Developers:** code and diffs, Mermaid architecture/sequence/ER diagrams, repository-linked examples, and interactive runnable prototypes where the project explicitly enables them.
- **Product roles:** flow maps, prioritisation, conversion funnels and metric charts including radar comparisons, three-measure segment and grouped part-to-whole comparisons, concise decision tables, and interactive prototypes for testing a concept.
- **General users:** readable prose first, with images, tables, and a chart only when they clarify the answer.

XLSX artifact previews show the first 100 columns and page 50 rows at a time. Users can combine the first one to five rows into column headings for stacked-header worksheets; merged heading values carry across their covered columns. Search scans up to 100,000 data rows across those visible columns; users can select a rectangular range across page boundaries when search is clear. Sending a range includes its workbook, worksheet, cell coordinates, column headings, values and up to 50 formula expressions. Users can choose from the first 40 worksheets or enter another sheet name. Merged cells whose full range fits on the current page render with row and column spans; ranges crossing a page or preview boundary remain separate and are called out. Very long values are shortened in the preview and excluded from range sharing so the source workbook remains authoritative. Keep provider-specific capabilities explicit, preserve provenance, and use the managed artifact boundary for durable outputs. OCR uses [RapidOCR](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/install/) with the CPU ONNX Runtime engine and [pypdfium2](https://pypdfium2-team.github.io/pypdfium2/) for page rendering; bundled model attribution and redistribution terms are recorded in `runtime/tribe_runtime/THIRD_PARTY_NOTICES.md`.
