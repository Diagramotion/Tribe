## Visual design principles

- Use `docs/design-language.md` as the concise design-system reference; keep its guidance aligned with the shared CSS tokens in `src/styles.css`.
- Tribe's design language is the **Workbench**: a calm navy canvas, compact tool chrome, readable task content and restrained blue emphasis. Use VS Code and Linear only as interaction and density references; do not mix their visual component styles.
- Use hierarchy, spacing, alignment and restrained colour to organise a screen before adding borders, dividers or cards.
- Prefer open layouts. Use a card only when it groups a distinct task or state; do not put cards inside cards or outline every row, control and message.
- Treat dividers as exceptions: add one only when spacing and alignment cannot distinguish separate regions. Keep it low contrast and continuous across the region it separates; avoid stacked or repeated horizontal rules.
- Use shared semantic status tokens across chat, project lists, provider settings, Git and run history. Ready/success, waiting/attention, error, active and neutral states must retain the same foreground and surface colour wherever they appear.
- Use the shared surface, selection, separator and focus tokens for common controls and hover states; do not add one-off shades for equivalent interactions in different views.
- Use a consistent spacing and control scale across views. Related items should be grouped by proximity, with clear but economical gaps between groups.
- Reserve stronger contrast and filled surfaces for the active or primary action. Keep secondary controls quiet, use icon buttons when the icon is recognisable, and provide an accessible label or tooltip.
- Use one clear scroll surface per pane where possible. Avoid nested scrolling and make the shared scrollbar treatment apply consistently.
- Review dense and split layouts at 1536×855 as well as the default desktop size. Keep the main task visible and preserve balanced padding when panes resize.
- Take colour, spacing, radius, focus and control-height values from shared CSS tokens. Add a token only for a repeated semantic role; do not create one-off near-duplicate shades or dimensions.
- Use `--text` for primary content, `--text-secondary` for supporting content, `--muted` and `--muted-2` for metadata, and the accent colours for active navigation or meaningful status. Do not use colour as decoration.
- Reuse shared button, icon-button, input, select and switch patterns. Use container queries for resizable pane layouts so split views adapt to pane width, not only the overall window.
